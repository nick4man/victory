# Подключение offsite-хранилища — runbook (09.08.26)

> Локальные бэкапы работают без этого шага. Offsite защищает от того, чего
> локальные копии не закрывают: потери CT 122 целиком и шифровальщика.
>
> Пока не выполнено, в конфиге стоит `OFFSITE_ENABLED=0`, и `bin/backup`
> пропускает выгрузку со строкой «offsite выключен, пропускаю».

## Почему российский S3, а не Google Drive и не Nextcloud

**Не зарубежное хранилище.** В базе ПДн граждан РФ — телефоны, email, а в
`client_documents` паспорта и ИНН из Telegram-приёмки. Ст. 18 ч. 5 152-ФЗ
требует, чтобы база с ПДн россиян находилась на территории России. Бэкап — та
же база. Клиентское шифрование снимает риск утечки, но вопрос локализации не
закрывает.

**Не Nextcloud и не VDS.** `cloud.victory62.org` и `victory62.org` резолвятся в
один адрес `45.10.247.42` — это одна машина. Копия туда дала бы не вторую точку
отказа, а ту же самую. Вдобавок на VDS диск 20 ГБ, свободно 5.1 ГБ при нужных
3.2 ГБ.

**Почему S3, а не Яндекс.Диск.** Object lock: объект нельзя удалить или
перезаписать до истечения срока даже валидными ключами. Это единственная защита
от шифровальщика, который добрался до сервера и пошёл по бэкапам.

## Шаги

### 1. Аккаунт и bucket

Selectel (`selectel.ru`) или Servercore. Создать объектное хранилище, регион —
российский. Создать bucket `victory-backups`, тип — приватный.

### 2. Включить versioning и object lock

Обязательно **до** первой заливки: на существующий bucket object lock в
большинстве провайдеров не включается.

- versioning — хранить предыдущие версии объектов;
- object lock в режиме governance, срок удержания — 30 суток.

### 3. Ключи доступа

Создать сервисного пользователя с доступом только к `victory-backups`, выпустить
S3-ключи (Access Key, Secret Key). Полный доступ к аккаунту скрипту не нужен.

### 4. Настроить rclone

```bash
rclone config
```

Первый remote — само хранилище:

```
name> victory-s3
Storage> s3
provider> Selectel          # или Other, если провайдера нет в списке
access_key_id> <Access Key>
secret_access_key> <Secret Key>
endpoint> s3.ru-1.storage.selcloud.ru    # взять из панели провайдера
```

Второй remote — шифрующая обёртка над первым:

```
name> victory-crypt
Storage> crypt
remote> victory-s3:victory-backups
filename_encryption> standard      # имена файлов тоже шифруются
directory_name_encryption> true
password> <тот же пароль, что в /etc/victory-backup/passphrase>
password2> <оставить пустым>
```

**Пароль crypt должен совпадать с содержимым `PASSPHRASE_FILE`.** Иначе ключей
станет два, и при восстановлении на чистой машине понадобятся оба — а забыть
можно любой.

Посмотреть текущий пароль:

```bash
cat /etc/victory-backup/passphrase
```

### 5. Проверить доступ

```bash
rclone lsd victory-crypt:
echo проверка > /tmp/проба.txt
rclone copy /tmp/проба.txt victory-crypt:
rclone cat victory-crypt:проба.txt      # должно вывести «проверка»
rclone delete victory-crypt:проба.txt
rm /tmp/проба.txt
```

В веб-панели провайдера при этом должен быть виден объект **со случайным
именем** — это подтверждает, что шифрование имён работает.

### 6. Включить

```bash
sed -i 's/^OFFSITE_ENABLED=0/OFFSITE_ENABLED=1/' /etc/victory-backup/backup.env
bin/backup all
```

Ожидается: `offsite → victory-crypt:victory-backups` и `offsite готов` вместо
«выключен, пропускаю».

### 7. Убедиться, что данные долетели

```bash
rclone ls victory-crypt:victory-backups/db        # имена читаемы: crypt расшифровывает на лету
rclone size victory-crypt:victory-backups
```

Первая выгрузка `storage` — 3.2 ГБ, займёт время. Последующие инкрементальны:
crypt шифрует пофайлово, поэтому летят только изменившиеся файлы.

### 8. Дописать в runbook восстановления

В `docs/runbooks/restore.md`, сценарий 2, указан `rclone copy` из
`victory-crypt:`. После настройки прогнать оттуда хотя бы скачивание одного
дампа и убедиться, что он расшифровывается — иначе сценарий останется
непроверенным.

## Сколько это стоит

При 3.2 ГБ файлов и ~70 МБ дампов — единицы гигабайт хранения. У российских
провайдеров это порядка 30–50 ₽ в месяц. Трафик на загрузку обычно бесплатен,
на скачивание — тарифицируется, но скачивание происходит только при аварии.

## Что проверить через месяц

```bash
rclone size victory-crypt:victory-backups
```

Если объём растёт быстрее ожидаемого — проверить, что lifecycle-правило на
bucket удаляет версии старше срока удержания. Иначе versioning будет копить все
когда-либо загруженные версии дампов.
