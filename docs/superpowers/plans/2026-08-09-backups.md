# Резервное копирование прода — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Регулярные шифрованные бэкапы прод-БД, файлов ActiveStorage и секретов с автоматической проверкой восстановления и уведомлениями в Telegram.

**Architecture:** Один bash-скрипт `bin/backup` с подкомандами, конфигурация из `/etc/victory-backup/backup.env`, запуск двумя systemd-таймерами (daily/weekly). Локальные копии на subvol `/`, offsite — в российский S3 через `rclone crypt`, включается флагом. Шифрование — gpg симметричный.

**Tech Stack:** bash, gpg, rsync, rclone 1.74.1, systemd 257, docker, PostgreSQL 15 (pg_dump/pg_restore), Telegram Bot API через curl.

## Global Constraints

- Спека: `docs/superpowers/specs/2026-08-09-backups-design.md` — при расхождении права спека.
- Даты в коде, выводе и сообщениях — `dd.MM.yy` (CLAUDE.md).
- Комментарии и пользовательский вывод — по-русски, как в `bin/chat-stack`.
- Прод-контейнеры **не останавливаются**: `pg_dump` работает по сети.
- Секреты **никогда** не печатаются в stdout/stderr и не попадают в логи.
- Локальные копии — в `/var/backups/victory` (subvol `/`), не в `/home`.
- Все зарубежные хранилища исключены (152-ФЗ, ПДн в схеме).
- Скрипт идемпотентен: повторный запуск не портит уже сделанное.
- `set -euo pipefail` во всех скриптах.

## File Structure

| Файл | Ответственность |
|---|---|
| `bin/backup` | единственная точка входа, все подкоманды |
| `config/backup.env.example` | образец конфигурации, коммитится |
| `/etc/victory-backup/backup.env` | реальная конфигурация, **не** в репозитории |
| `/etc/victory-backup/passphrase` | пароль gpg, владелец `q`, `0600`, **не** в репозитории |
| `deploy/systemd/victory-backup-daily.service` / `.timer` | БД + секреты, ежедневно |
| `deploy/systemd/victory-backup-weekly.service` / `.timer` | файлы + verify, еженедельно |
| `docs/runbooks/restore.md` | процедура восстановления, проверенная руками |

```bash
#!/usr/bin/env bash
#
# Резервное копирование прода victory62.
#
#   bin/backup db          дамп PostgreSQL → gpg
#   bin/backup secrets     .env + credentials → gpg
#   bin/backup files       storage: локальный снапшот (+ offsite, если включён)
#   bin/backup all         всё разом; это вызывают таймеры
#   bin/backup verify      восстановить последний дамп и сверить
#   bin/backup restore     интерактивное восстановление
#   bin/backup status      что есть, когда сделано, сколько весит
#
# Дизайн: docs/superpowers/specs/2026-08-09-backups-design.md
set -euo pipefail

CONFIG_FILE="${BACKUP_CONFIG:-/etc/victory-backup/backup.env}"

log()  { printf '%s %s\n' "$(date '+%d.%m.%y %H:%M:%S')" "$*"; }
die()  { log "ОШИБКА: $*" >&2; exit 1; }
ts()   { date '+%d.%m.%y-%H%M'; }

load_config() {
  [ -r "$CONFIG_FILE" ] || die "нет конфига $CONFIG_FILE (образец: config/backup.env.example)"
  # shellcheck disable=SC1090
  set -a; . "$CONFIG_FILE"; set +a
  : "${BACKUP_ROOT:?не задан BACKUP_ROOT}"
  : "${DB_CONTAINER:?не задан DB_CONTAINER}"
  : "${DB_NAME:?не задан DB_NAME}"
  : "${APP_ROOT:?не задан APP_ROOT}"
  : "${PASSPHRASE_FILE:?не задан PASSPHRASE_FILE}"
}

# Каталоги создаём заранее, чтобы подкоманды не дублировали mkdir.
ensure_dirs() {
  mkdir -p "$BACKUP_ROOT"/{db,secrets,files,logs,tmp}
}

cmd_status() {
  load_config
  printf 'Хранилище: %s\n\n' "$BACKUP_ROOT"
  local d
  for d in db secrets files; do
    printf '%-9s %6s  последний: %s\n' \
      "$d" \
      "$(du -sh "$BACKUP_ROOT/$d" 2>/dev/null | cut -f1 || echo '—')" \
      "$(ls -t "$BACKUP_ROOT/$d" 2>/dev/null | head -1 || echo 'нет копий')"
  done
  printf '\nOffsite: %s\n' "$([ "${OFFSITE_ENABLED:-0}" = 1 ] && echo "включён → ${OFFSITE_REMOTE}" || echo 'выключен')"
  printf 'Свободно на %s: %s\n' "$BACKUP_ROOT" "$(df -h "$BACKUP_ROOT" | awk 'NR==2{print $4}')"
}

cmd_help() { sed -n '3,12p' "$0"; }

cmd="${1:-help}"; shift || true
case "$cmd" in
  status) cmd_status "$@" ;;
  help|--help|-h) cmd_help ;;
  *) die "неизвестная команда '$cmd'. См. bin/backup help" ;;
esac
```

- [ ] **Step 2: Добавить функции шифрования и ротации**

```bash
# Шифруем поток, а не файл: незашифрованный дамп на диске не появляется даже
# на секунду. gpg симметричный — ключей-пар не нужно, пароль один.
encrypt_to() {
  local dest="$1"
  gpg --batch --yes --quiet \
      --symmetric --cipher-algo AES256 \
      --passphrase-file "$PASSPHRASE_FILE" \
      --output "$dest"
}

# Оставляем N самых свежих файлов в каталоге, остальные удаляем.
# По времени модификации, а не по имени: имя содержит dd.MM.yy и лексикографически
# не сортируется по возрасту.
prune() {
  local dir="$1" keep="$2" file
  ls -t "$dir" 2>/dev/null | tail -n "+$((keep + 1))" | while read -r file; do
    log "  ротация: удаляю $file"
    rm -f -- "$dir/$file"
  done
}
```

```bash
cmd_db() {
  load_config; ensure_dirs
  local dest="$BACKUP_ROOT/db/viktory-$(ts).dump.gpg"
  log "дамп $DB_NAME из $DB_CONTAINER"

  # -Fc: сжатый custom format, позволяет частичное восстановление.
  # Работает по сети внутри контейнера, прод не останавливается.
  docker exec "$DB_CONTAINER" \
      pg_dump -U "$DB_USER" -Fc --no-owner --no-acl "$DB_NAME" \
    | encrypt_to "$dest"

  [ -s "$dest" ] || die "дамп пустой: $dest"
  log "готово: $dest ($(du -h "$dest" | cut -f1))"
  prune "$BACKUP_ROOT/db" "${KEEP_DAILY:-7}"
}
```

```bash
  # -C + относительные пути: при восстановлении не тянем /home/q/victory наружу.

  [ -s "$dest" ] || die "архив секретов пустой: $dest"
  log "готово: $dest ($(du -h "$dest" | cut -f1))"
  prune "$BACKUP_ROOT/secrets" "${KEEP_DAILY:-7}"
}
```

### Task 3: `backup files` — снапшоты storage на жёстких ссылках

**Interfaces:**
- Consumes: `log()`, `die()`, `ts()`, `load_config()`, `ensure_dirs()`, `prune()`
- Produces: подкоманда `files`; каталоги вида `files/storage-<dd.MM.yy-HHMM>/`, симлинк `files/latest`

- [ ] **Step 1: Добавить подкоманду `files`**

```bash
cmd_files() {
  load_config; ensure_dirs
  local src="$APP_ROOT/storage"
  [ -d "$src" ] || die "нет каталога $src"

  local dest="$BACKUP_ROOT/files/storage-$(ts)"
  local link_arg=()
  # --link-dest: неизменившиеся файлы становятся жёсткими ссылками на предыдущий
  # снапшот. Четыре недельных копии 3.2 GB занимают немногим больше одной.
  [ -d "$BACKUP_ROOT/files/latest" ] && link_arg=(--link-dest="$BACKUP_ROOT/files/latest")

  log "снапшот storage → $dest"
  rsync -a --delete "${link_arg[@]}" "$src/" "$dest/"

  ln -sfn "$dest" "$BACKUP_ROOT/files/latest"
  log "готово: $(du -sh "$dest" | cut -f1) (реально нового: $(du -sh --exclude-from=/dev/null "$dest" | cut -f1))"

  # latest — симлинк, ротации не подлежит; prune работает по mtime и его не тронет,
  # но для надёжности исключаем явно.
  prune_files_snapshots
}

# Отдельно от prune(): здесь каталоги, а не файлы, и есть симлинк latest.
prune_files_snapshots() {
  local keep="${KEEP_WEEKLY:-4}" dir
  find "$BACKUP_ROOT/files" -maxdepth 1 -type d -name 'storage-*' -printf '%T@ %p\n' \
    | sort -rn | tail -n "+$((keep + 1))" | cut -d' ' -f2- | while read -r dir; do
      log "  ротация: удаляю $(basename "$dir")"
      rm -rf -- "$dir"
    done
}
```

- [ ] **Step 1: Добавить подкоманду `verify`**

```bash
# Список таблиц для сверки. Не все 100+, а те, потеря которых видна бизнесу.
VERIFY_TABLES='properties users inquiries conversations property_valuations'

cmd_verify() {
  load_config
  local dump; dump=$(ls -t "$BACKUP_ROOT"/db/*.dump.gpg 2>/dev/null | head -1) \
    || die 'нет ни одного дампа'
  [ -n "$dump" ] || die 'нет ни одного дампа'
  log "проверяю $(basename "$dump")"

  local cname="victory-verify-$$"
  # Одноразовый контейнер того же образа, что и прод — иначе не проверим расширения.
  docker run -d --rm --name "$cname" \
    -e POSTGRES_PASSWORD=verify -e POSTGRES_DB=verify \
    viktory-postgres-pgvector:pg15-postgis35 >/dev/null
  # shellcheck disable=SC2064
  trap "docker rm -f '$cname' >/dev/null 2>&1 || true" RETURN

  local i
  for i in $(seq 1 60); do
    docker exec "$cname" pg_isready -U postgres -q && break
    [ "$i" = 60 ] && die 'контейнер проверки не поднялся за 60 с'
    sleep 1
  done

  log '  восстанавливаю дамп'
  gpg --batch --quiet --decrypt --passphrase-file "$PASSPHRASE_FILE" "$dump" \
    | docker exec -i "$cname" pg_restore -U postgres -d verify --no-owner --no-acl \
    >/dev/null 2>"$BACKUP_ROOT/tmp/verify-restore.log" || true
  # pg_restore возвращает ненулевой код на безобидных warning'ах (отсутствующие
  # роли), поэтому судим по фактическому результату, а не по коду возврата.

  log '  проверяю расширения'
  local ext missing=''
  for ext in postgis vector pg_trgm unaccent; do
    docker exec "$cname" psql -U postgres -d verify -tAc \
      "SELECT 1 FROM pg_extension WHERE extname='$ext'" | grep -q 1 || missing="$missing $ext"
  done
  [ -z "$missing" ] || die "в восстановленной базе нет расширений:$missing"

  log '  сверяю количество строк'
  local t live restored bad=''
  for t in $VERIFY_TABLES; do
    live=$(docker exec "$DB_CONTAINER" psql -U "$DB_USER" -d "$DB_NAME" -tAc \
      "SELECT COUNT(*) FROM $t" 2>/dev/null || echo 0)
    restored=$(docker exec "$cname" psql -U postgres -d verify -tAc \
      "SELECT COUNT(*) FROM $t" 2>/dev/null || echo 0)
    # Тревога только если в КОПИИ меньше — это признак усечённого дампа.
    # Обратное (в проде стало меньше) законно: soft-delete, архивация, 152-ФЗ.
    if [ "$live" -gt 0 ] && [ "$restored" -lt $((live * 90 / 100)) ]; then
      bad="$bad $t(копия=$restored прод=$live)"
    fi
    log "    $t: копия=$restored прод=$live"
  done
  [ -z "$bad" ] || die "в копии существенно меньше строк:$bad"

  log 'проверка пройдена'
}
```

```bash
# Через curl, а не через Rails/Sidekiq: бэкап обязан работать, когда приложение
# лежит — именно тогда он и нужен.
notify() {
  local text="$1"
  [ -n "${TELEGRAM_BOT_TOKEN:-}" ] && [ -n "${TELEGRAM_STAFF_CHAT_ID:-}" ] || {
    log 'уведомления не настроены, пропускаю'; return 0; }
```

```bash
# Ежедневно: БД + секреты. Провал любого шага — сообщение немедленно.
#
# ВАЖНО: шаги вызываются в подоболочке ( ... ). Внутри cmd_db/cmd_secrets ошибка
# идёт через die(), а die делает `exit 1` — он завершил бы ВЕСЬ скрипт, и
# `|| failed=...` никогда бы не отработал, то есть уведомление о провале не ушло
# бы ни разу. В подоболочке exit гасит только её, код возврата ловится.
cmd_all() {
  load_config
  local failed=''
  ( cmd_db )      || failed="$failed БД"
  ( cmd_secrets ) || failed="$failed секреты"
  if [ -n "$failed" ]; then
    notify "🔴 <b>Бэкап victory62 провалился</b>%0Aне сделано:$failed%0A$(date '+%d.%m.%y %H:%M')"
    die "провал:$failed"
  fi
  log 'ежедневный бэкап готов'
}

# Еженедельно: файлы + проверка восстановления + сводка.
cmd_weekly() {
  load_config
  local failed=''
  ( cmd_files )  || failed="$failed файлы"     # подоболочка — см. cmd_all выше
  ( cmd_verify ) || failed="$failed проверка-восстановления"
  if [ -n "$failed" ]; then
    notify "🔴 <b>Еженедельный бэкап victory62 провалился</b>%0Aне сделано:$failed%0A$(date '+%d.%m.%y %H:%M')"
    die "провал:$failed"
  fi
  # Сводка при УСПЕХЕ обязательна: молчащий бэкап неотличим от сломанного.
  notify "$(printf '🟢 <b>Бэкап victory62 за неделю</b>\n%s\nСвободно: %s' \
            "$(cmd_status)" "$(df -h "$BACKUP_ROOT" | awk 'NR==2{print $4}')")"
}
```

- [ ] **Step 2: Добавить `offsite_sync()`**

```bash
# rclone crypt шифрует пофайлово, поэтому sync остаётся инкрементальным:
# летят только изменившиеся файлы, а не 3.2 GB каждую неделю.
offsite_sync() {
  [ "${OFFSITE_ENABLED:-0}" = 1 ] || { log 'offsite выключен, пропускаю'; return 0; }
  : "${OFFSITE_REMOTE:?не задан OFFSITE_REMOTE}"

  log "offsite → $OFFSITE_REMOTE"
  # Дампы и секреты уже зашифрованы gpg; crypt поверх — второй слой, он дешёвый
  # и скрывает заодно имена файлов.
  rclone sync "$BACKUP_ROOT/db"      "$OFFSITE_REMOTE/db"      --transfers 4 --stats-one-line
  rclone sync "$BACKUP_ROOT/secrets" "$OFFSITE_REMOTE/secrets" --transfers 4 --stats-one-line
  # Файлы — только последний снапшот: старые версии держит versioning на bucket.
  rclone sync "$BACKUP_ROOT/files/latest/" "$OFFSITE_REMOTE/storage" \
    --transfers 8 --stats-one-line
  log 'offsite готов'
}
```
