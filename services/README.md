# services/ — подсистемы вне Rails

Один репозиторий, много маленьких служб. Не путать с `app/services/` — там
Ruby-объекты доменной логики внутри Rails.

| Служба | Язык | Перенос | Срок |
|---|---|---|---|
| `audit-engine/` | Python (FastAPI) | не начат | 31.03.27 |
| `chat-host-cron/` | bash | завершён | — |
| `urgent-news-collector/` | Python | завершён | — |
| `web-comparables/` | текст скилла, кода нет | завершён | — |

Владелец у всех один — **victory**. Подробности каждой службы — в её
`SERVICE.md`.

## Четыре правила

**1. Каждый каталог под `services/` имеет `SERVICE.md`.** Манифест лежит
внутри службы намеренно, а не сводится в общий файл: в worktree
`victory-urgent-collector` включён sparse-checkout, и этот README туда не
попадает вовсе, а `services/urgent-news-collector/SERVICE.md` — попадает
вместе со службой. Политика обязана жить там, где её увидят.

**2. Владелец всегда victory.** Внешний источник указывается в `ported_from`
и никогда в `owner`. Это не формальность: пока файл числится в двух
репозиториях, у него два владельца, что бы ни было написано в заголовке.
Именно так два каталога из четырёх годами объявляли себя чужими, лёжа в
нашем дереве.

**3. Службы не знают друг о друге.** `depends_on: none` — не пожелание, а
проверяемое условие. Связь между службами идёт через контракт: вебхук, HTTP,
формат файла. Импорт соседней службы или Rails-кода роняет проверку. Как
только одна служба начинает импортировать другую, «много маленьких» тихо
превращается в «один большой», и обратно уже не разбирается.

**4. Незавершённый перенос имеет дату.** `port_status` не `done` требует
`repatriate_by`, и после этой даты `bin/services-check` начинает ругаться.
Без срока «потихоньку доведём до ума» означает «никогда» — а с ним
продление становится осознанным решением, которое видно в диффе.

## Проверка

```
bin/services-check
```

Нужен только `python3` — Ruby не требуется намеренно: проверка обязана
работать и там, где Ruby на машине нет. Гоняется в CI на каждый PR.

## openclaw: архив, а не апстрим

Репозиторий `github.com/nick4man/openclaw` напрямую больше не правится.
Права на весь код, писавшийся для агентства, — здесь; тот репозиторий мы
постепенно разбираем, доводя службы до ума и перенося к себе.

07.09.26 пришлось отдельно проговорить, что **репозиторий openclaw и каталог
openclaw на диске — разные вещи**: каталог
`/opt/.openclaw/…/workspace-conveyor/IT/scripts` тогда остался боевым, целью
деплоя. Смешение этих двух смыслов и размыло владение: скрипт назывался
«сверкой двух копий», хотя одна из копий была продакшеном.

**11.09.26 разделение снято: архив — и каталог тоже.** `/opt/.openclaw/.openclaw/**`
доступен только на чтение, писать туда нельзя. Конвейер новостей выкатывается
из git в `/opt/victory-conveyor` (`services/urgent-news-collector/deploy.sh`);
`sync-check.sh` отключён вместе с режимом `--deploy`, `upstream-sync.sh` службы
audit-engine — тоже. Запрет продублирован в `.claude/settings.json`
(`permissions.deny`) — и на скрипты, и на запись в каталог архива.

⚠️ Хвост: живой контейнер `audit-v2-api` пока поднят из архива. Переезд стека
отдельным шагом — `services/audit-engine/VENDOR.md`.
