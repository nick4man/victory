# urgent-news-collector

Конвейер срочных новостей для канала `@rznvictory` и витрины victory62.org.
Тянет RSS деловых изданий, отбирает то, что реально касается рынка
недвижимости, и публикует. Всё остальное уходит в дайджест или в архив.

Продюсер для эндпоинта `app/controllers/webhooks/news_ingest_controller.rb`
из этого же репозитория: опубликованный пост зеркалится на сайт через
`mirror_to_victory`.

## Как устроено

Два независимых процесса, оба по крону, связаны только через БД.

**`urgent_collector.py`** — раз в 30 минут. Читает 7 лент, каждую новость
прогоняет через LLM-классификатор и раскладывает по четырём корзинам:

| Корзина | Что это |
|---|---|
| `URGENT` | публикуем немедленно |
| `DIGEST` | пойдёт в еженедельный обзор |
| `ARCHIVE` | сохраняем как контекст, не публикуем |
| `NOISE` | выбрасываем |

Ленты и их вес: ЦБ РФ, РБК Недвижимость, Ведомости.Финансы, РИА Недвижимость
(`high`), Интерфакс, РБК Экономика (`medium`), Forbes (`low`).

**`urgent_trigger.py`** — каждые 15 минут. Берёт до 10 необработанных
`URGENT`-событий, генерирует пост, публикует в Telegram и зеркалит на сайт.
Лимит в 10 кандидатов, а не в 1 — чтобы одна отклонённая новость не съедала
весь цикл.

## Детерминированный фильтр

Ключевая часть — `urgent_relevance.py`. Это чистые функции без сети и БД:
единственный источник правды о том, что достойно пометки «⚡СРОЧНО».
Вызывается **дважды** — в коллекторе сразу после LLM и в триггере перед
публикацией. Второй вызов страхует от ошибок классификатора и от строк,
попавших в базу до появления фильтра.

Срочными могут быть только пять типов событий:

```
KEY_RATE  LAW_UPDATE  TAX_CHANGE  MORTGAGE_POLICY  CAPITAL_CONTROL
```

Всё прочее, что классификатор вправе вернуть (`FX_RATE`, `MACRO_ECONOMICS`,
`EXPERT_ANALYSIS`, `MARKET_TREND`, `OFF_TOPIC`, `NONE`), срочным не бывает
по определению. Незнакомый тип — тоже отказ: так «модель выдумала значение»
отличается от «известный, но не публикуемый».

Поверх типа работают три эвристики отсева: `is_fx_noise` (курсовая рутина),
`is_equity_noise` (фондовый рынок) и `is_non_event` — цитирования документов
ЦБ, бюллетени, индексы проектов НПА и ежедневные сводки.

Граница проведена сознательно: **недвижимость и прямые ограничения на
капитал клиента**. Ни геополитики, ни акций. Молчание — нормальный исход,
дневного лимита и «добора до минимума» нет.

Замер на 30 днях: было 84 срочные публикации, стало 14. Ни одно событие по
ключевой ставке и жилищному законодательству не потеряно.

## Дедупликация

`gemini-embedding-001` + pgvector, косинусная близость, порог **0.92**.
Якорями служат только реально опубликованные события (`published_to_tg = TRUE`).

Оба числа выстраданы. Порог 0.85 резал валидные новости: на коротких русских
официальных заголовках baseline держится около 0.85+ просто из-за общего
лексикона («Банк России», «Указание», числа, даты). Истинные дубли — от 0.93.
А без привязки к `published_to_tg` зарезанные дедупом события сами становились
якорями для следующих: однажды это дало 4 дня тишины и ~31 потерянное событие.

## Отказоустойчивость LLM

`complete_with_fallbacks` в `pipeline_utils.py` обходит цепочку провайдеров
сверху вниз до первого валидного ответа: три бесплатные модели Google, затем
Cloudflare и omniroute, затем Gemini Pro и последним — платный
`anthropic/claude-sonnet-4`. Платное звено помечено в `PAID_MODELS` и
дёргается только когда всё бесплатное отказало.

## Данные

Две базы:

- **База новостей** (`NEWS_DB_*`, pgvector) — таблица `urgent_events`:
  заголовки, корзина, тип события, эмбеддинг, флаги `is_processed` и
  `published_to_tg`.
- **Продакшн-база** (`DB_*`) — `posts_queue` и `system_flags`.

Если `NEWS_DB_*` не заданы, код падает обратно на `DB_*`.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env      # заполнить; .env в git не попадает
```

Расписание — в `crontab.example`. `flock -n` обязателен: холодный старт
коллектора идёт несколько минут, и прогоны не должны накладываться.

## Проверка

```bash
python3 -m unittest test_urgent_relevance -v     # 26 тестов, без сети и БД
```

Тесты гейта релевантности зависимостей не требуют — системного `python3`
достаточно. Виртуалка нужна для самого конвейера и для бэктеста.

`backtest_urgent_relevance.py` прогоняет текущий классификатор по уже
собранным событиям и считает обе ошибки — и лишние публикации, и пропущенные.
Нужен доступ к базе новостей. `--json` принимает путь к файлу, без него
результат только в stdout.

```bash
.venv/bin/python backtest_urgent_relevance.py --days 30 --json /tmp/backtest.json
```

Важно: в поле `details` осевших событий записан вердикт **прежнего**
классификатора. Харнесс вырезает его перед повторным прогоном — иначе замер
меряет сам себя.

## Эксплуатация

Логи — `urgent_collector.log` и `urgent_trigger.log`.

Пустой прогон выглядит так и это норма:

```
INFO - No unhandled urgent events found.
```

А вот это значит, что у машины нет DNS, и конвейер стоит:

```
WARNING - Malformed feed from Новости ЦБ РФ: <urlopen error [Errno -3] Temporary failure in name resolution>
```

Отличать одно от другого стоит по факту вставок: строки `Inserted [...]` в
логе коллектора есть — ленты читаются.
