## 1. Логика отправки всех запросов в Topnlab и
формат ответа
Важно! Базовые принципы работы с API

Каждый метод API принимает на вход данные и отвечает результатом обработки этих данных.
Тип запросов к API: POST, формат данных - JSON.
Формат ответа бывает четырех видов:
## 1. Успех
## 2. Успех с предупреждением
## 3. Некорректные данные
## 4. Ошибка

Успех.
Все хорошо, все поля заполнены.
Код ответа 200

```
{
    "status": "ok",
}

Успех с предупреждениями
```
Метод отработал, но есть ошибки в необязательных полях
Код ответа 200

```
{
  "status": "ok",
  "errors": [
    "object_id": "Передан id несуществующего объекта, по которому был
звонок"
  ]
}
```
Некорректные значения полей.
Необходимо повторить запрос, исправив значения полей.

Такая ошибка возникает если параметр обязательный и данные должны быть корректными. Без
этого параметра нельзя получить "status": "ok", И это значит что на стороне Topnlab действие
не выполнено!!
Код ответа 422

```
{
    "status": "error",
    "errors": [
      "action": "Не указан тип сделки заявки"
    ]
}
```
Ошибка
Необходимо повторить запрос через несколько минут, если получили любую другую ошибку
которая не регламентировано документацией
Код ответа ЛЮБОЙ КРОМЕ! 200 и 422

```
Формат ошибки может быть любым в том числе и "Без ответ". "Без ответа"
тоже считаем как ошибка,
в следствии чего необходимо повторить запрос.

2. Создание Заявок в Topnlab
```
POST: https://agencies-p.topnlab.ru/call/main/importClient/
Формат запроса

```
{
    "appkey": "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX", // Ключ API
    "fullname": "Тётя Ася", // ФИО
    "phone": "79269998877", // Телефон
    "action": 0, // 0 - звонок по аренде, 1 - по продаже
    "object_type": "flat", // Тип недвижимости (описание типов см. ниже)
    "comment": "ищет для сына", // комментарий к заявке (не более 500
символов)
    "comment_public": "публичный комментарий", // комментарий к заявке
(не более 500 символов)
    "called_for_object_short_id": 53020, // id объекта, по которому был
звонок
    "to_number": "8127778899" // Необязательное - На какой номер колл-
центра звонили, номер без +7
}
```
Типы недвижимости flat - квартира, room - комната, commerce - коммерция, house -
загородка, land - участок, garage - машиноместо/гараж
Формат ответа

```
{
    "status": "ok",
    "insertedId": 100500 // id созданной заявки
}
```

### 3.2. Назначение объекту короткого id
Этот метод присваивает объектам кастомные идентификаторы. Это используется в том случае,
если на стороне клиента есть своя нумерация объектов в системе. В других методах можно
передавать как полный id объекта, так и короткий.
POST: https://agencies-p.topnlab.ru/call/main/bindShortNumber/
Формат запроса

```
{
      "appkey": "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX", // Ключ API
      "short_id": 123, // Новое значение короткого идентификатора
      "object_id": 31702519 // id объекта
}
```
Формат ответа

```
{
    "status": "ok"
}
```

## 6. Передача клиентов через формы обратной
связи в Topnlab
```
 1. Логика передачи данных о клиентах через форму обратной связи и/или из других источников
    по мимо звонков осуществляется тем же способом что при звонке. За исключением одной
    особенности.
       1. Особенность!
            1. При передаче информации о создании карточки в Topnlab в поле "Рекламный
               источник" значение определяется по номеру телефона, которая приходит вместе с
               сущностью "Звонок"
            2. При создании карточки из других источников нет сущности "Звонок" и для
               определения значения поля "Рекламный источник" необходимо вместе с данными
               карточки передавать еще значение для поля to_numberв этом поле передаете
               Номер телефона в формате +7 ХХХХХХХХХХ который соответсвует
               рекламному источнику который создан в разделе "Настройки системы" -->
               "рекламные источники" по этому номеру система определит источник если это
               был не звонок.
```
## 7. Получение API-ключей от досок объявлений
Для получения авторизационных данных можно сделать запрос
POST
https://agencies-p.topnlab.ru/public/partner/0000/credentials?site=AVITO
Где 0000 - это идентификатор вашей компании, key - ключ API, а site - опциональный
параметр для фильтрации досок по их uid. Примеры значений: AVITO,CIAN,BANK,YANDEX


## 8. Получение данных недвижимости и
ответственного агента по идентификатору с



```
рекламной доски
```
Для получения данных по объекту недвижимости, имея идентификатор публикации с рекланой
доски (Авито, ЦИАН, Яндекс и иные, для которых подключено получение обратных ссылок через
API) необходимо сделать запрос:
GET
https://agencies-p.topnlab.ru/call/main/avitoData/?publication_id=112233&k
ey=ВАШКЛЮЧ
Где publication_id - идентификатор публикации на рекламной доске, а key -- ключ API
Формат ответа:

```
{
  "status": "ok",
  "result": {
    "realty: { // Данные недвижимости, стандартный набор полей
       "id": 123,
       "action": "sale",
       "company_id": 5566,
       "deal_state": "active"
       ...
    },
    "user": { // Данные ответственного сотрудника, стандартный набор
полей
       "id": 123,
       "email: "ielfa81@gmail.com",
       "foreign_id: null, // id во внешней системе, если указан
       "fathername: "Отчетство",
       "lastname: "Фамилия"
       "name: "Имя"
       "phone: "79274000000"
       ...
    }
  }
}
```
Если такое размещение не найдено, возвращается информация об ошибке

```
{
    "status": "error",
    "errors": [
      "publication_id": "Не нашлось такого размещения"
    ]
}
```
