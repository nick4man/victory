## Findings

### 🔴 P0 — `fetchpriority="high"` conflict (FIXED `92f6e70`)

**Issue:** /properties отдавал 2 cards с `loading="eager" fetchpriority="high"`,
/premium отдавал 3 cards с тем же. Lighthouse spec: только ОДНА image на
странице должна иметь `fetchpriority="high"` — это LCP candidate signal.
Multiple high-priority images конкурируют за bandwidth → замедление LCP
особенно на 4G mobile.

**Root cause:** `properties/index.html.erb` использовал `i < 2`,
`premium/index.html.erb` — `idx < 3`. Идея была "mark above-fold cards",
но fetchpriority="high" — это сильнее чем нужно для cards 2+.

**Fix applied:**
- `properties/index.html.erb`: `i.zero?`
- `premium/index.html.erb`: `idx.zero?`

Cards 2-3 above-fold всё ещё загружаются eager через browser preload
(default behavior без explicit fetchpriority). Cards 4+ lazy (unchanged).

### 🟡 P1 — Yandex.Метрика snippet position (not fixed)

**Observation:** 1 blocking `<script type="text/javascript">` в `<head>`
на главной — likely Я.Метрика async snippet, но classified as "blocking"
по наличию `inline` (без async/defer/module attributes).

**Not fixing** — Я.Метрика официально работает только в `<head>` для
точности первой загрузки. Defer/async ломает её session tracking.

### 🟢 OK — Responsive images

Cards 2+ имеют правильный `srcset="...400w...800w...1920w"` + `sizes`
attribute. Loading attributes корректные (lazy для below-fold).

### 🟢 OK — Photo slider eager discipline

`shared/_photo_slider.html.erb` правильно эмитирует `loading="eager"
fetchpriority="high"` только для i=0 (verified в earlier commit).
