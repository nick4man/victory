# Базовая линия по показам — как запустить и как читать

Срок: 2 недели с даты деплоя стеков A+B. Фильтр (`SHOW_ROUTING_ENABLED`) выключен — кто ездит на показы,
не меняется. Реализация: `docs/superpowers/plans/2026-09-11-show-delegation-telegram.md`, решения —
`BOTTLENECK.md` рядом.

## Что делают люди (три действия, всё в Telegram)

1. **Сегмент покупателя** — кнопка под карточкой лида в #ДИСПЕТЧЕРСКОЙ (💵 Нал / 🏦 Ипотека ✓ / ⏳ Ипотека ? /
   🔄 Альт / ❄️ Холод) или `/segment наличные`. Бот напомнит сам при переходе в «показ».
2. **Стадия** — кнопки 📅 Показ / ✍️ Договор под карточкой (или `/stage показ`).
3. **Отчёт после показа** — голосовое боту в личку (принимается от любого активного сотрудника) или
   `/show <id> текст`. Бот покажет превью → ✅ Сохранить. Дальше сам: стадия, задача «собственнику до 11:00»,
   черновик сообщения собственнику с кнопкой отправки.

## Что делает бот

- Понедельник 10:00, DM директору — блок «Показы»: показ→договор по ячейкам «сегмент × кто показывал»,
  объекты без показов 30 дней, медиана дней от публикации до первого показа, объекты с ≥3 показами без
  договора, показы без отчёта.
- `/objections` reply на карточку — «7 показов · 5× кухня · 4× первый этаж», исходы, названные цены.
- Просрочка «собственнику до 11:00» — пинг от `Sla::TasksWatchdogJob`.
- Неподтверждённый отчёт старше часа снимается в `expired` тем же кроном, что чистит `TaskBatch`
  (`TaskBatchExpiryJob`, каждые 10 минут) — иначе «показов без отчёта» врёт при живом превью.

## Как читать цифры (три ловушки из BOTTLENECK.md)

- Сравнивать **только внутри сегмента**: строка «❄️ Холодный — руководитель: 1/6 · агент: —» через две недели
  станет «руководитель (до) ↔ агент (после)». Сводной цифры «конверсия агента» в отчёте нет намеренно.
- Ячейка меньше 5 показов — шум, не разница.
- Главная метрика — конверсия показ→договор, она защищена сама собой: раздувать показы выгодно ровно до
  момента, когда портишь собственную цифру. «Показ проведён» без отчёта виден отдельной строкой.

## Когда включать фильтр

Оба условия: прошло ≥ 14 дней **и** `ShowReport.status_confirmed.count >= 20`.

Проверка:

```bash
bin/rb --db bin/rails runner 'p ShowReport.status_confirmed.count, ShowReport.status_confirmed.minimum(:conducted_at)'
```

Включение: `SHOW_ROUTING_ENABLED=true` в `.env`, рестарт web и sidekiq. После включения при переходе в «показ»
бот предлагает «кто поедет» с кнопками; `/bargain 5,2 млн` — карточка руководителю за секунду до звонка с объекта.

## Что проверить перед стартом

- `LLM_CHAIN_STAFF_ANALYSIS` задан в проде. Без него `Llm::OmniClient` **молча** берёт цепочку `:chat` —
  извлечение отчёта из голоса деградирует без единой ошибки в логах.
- `Sla::TasksWatchdogJob` реально гоняется. 🚨 На 13.09.26 — **нет**: он был объявлен только в
  `config/schedule.rb`, который никогда не исполнялся (гема `whenever` нет) и удалён. Нужна строка в
  `config/sidekiq_cron.yml` (см. PR #64) — иначе обещание «напомним про собственника» не выполняется.
- После деплоя — `bin/rails telegram:sync_commands`, иначе новые команды не появятся в «/»-меню.

## Самое рискованное допущение

Если через 6–8 недель после включения разница конверсий внутри сегментов окажется в пределах шума, решение
принимается по стоимости времени руководителя, а не по цифрам. Это нормальный исход; не путать отсутствие
сигнала с отсутствием эффекта.
