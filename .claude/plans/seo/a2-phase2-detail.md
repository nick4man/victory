# A2 Фаза 2 — админка ЖК, плюс срочная починка блок-редактора

> Канонический документ по A2 целиком — `.claude/plans/seo/a2-zhk-landings.md` в репозитории. Здесь — детализация Фазы 2; после утверждения переносится туда.

## Context

Фаза 1 (справочник ЖК: модель, связь с `Property`, сиды, спеки) вмержена — `6928c55`. Фаза 2 по плану даёт админку, без которой справочник нечем наполнять: 7 засеянных ЖК лежат черновиками с пустой фактурой, а гейт Фазы 3 — «≥3 ЖК с собственным текстом» — достижим только руками редактора.

Разведка перед началом вскрыла **постороннюю проблему, которая блокирует работу**: в блок-редакторе админки лендингов заряжена потеря контента. `app/views/admin/landing_contents/_form.html.erb:126` читает начальные блоки через `document.currentScript.dataset` внутри `<script type="module">`, где `currentScript` по спеке всегда `null`. `TypeError` глотается пустым `catch` (:128), `STATE.blocks` остаётся пустым, финальный `render()` (:317) вызывает `commit()` (:183) и записывает в скрытое поле `[]`. Контроллер (`admin/landing_contents_controller.rb:117-125`) принимает это `[]` и перетирает `body_blocks`, а concern `RendersLandingBlocks` обнуляет `body_html`/`body_plain`.

В проде 20 строк `landing_contents`, все опубликованы, все с блоками; `MAX(updated_at)` = 13.05.26 — через админку с тех пор не сохраняли, поэтому мина ещё не сработала. Первый редактор, открывший любой лендинг и нажавший «Сохранить», сотрёт его текст.

Это ровно тот код, который Фаза 2 извлекает в общий партиал. Поэтому работа разбивается на два PR: сначала починка, потом извлечение уже исправленного.

Решения пользователя: **починка отдельным PR сейчас**; привязка объектов к ЖК — **только с экрана ЖК** (формы редактирования `Property` в админке не существует, `app/views/admin/properties/` — это `index` + `request_consent`).

## PR-A — починка блок-редактора

### Механизм

Начальное состояние переезжает в `value` того самого скрытого поля, которое редактор сериализует. `data-lc-initial` и `raw()` удаляются.

`_form.html.erb:77`:
```erb
<%= hidden_field_tag 'landing_content[body_blocks_json]',
      (landing_content.body_blocks || []).to_json, id: 'lc-blocks-json' %>
```

`_form.html.erb:122` — `<script type="module">` без атрибутов; внутри IIFE **сначала** все `getElementById`, потом парсинг. Порядок критичен: сегодня `jsonEl` объявлен на :131, ниже try-блока на :126, и наивная починка «читать из hidden-поля» без перестановки дала бы `ReferenceError` по TDZ — тот же тихий отказ, съеденный тем же `catch`.

Пустой `catch` убираем: при ошибке парсинга ставим флаг, **не** вызываем `render()` (а значит и `commit()`), вместо этого рисуем в `#lc-blocks` красную плашку «Редактор не смог загрузить блоки — не сохраняйте страницу». Тихая потеря превращается в видимый отказ.

Почему `value`, а не `dataset` на wrapper-div: если модуль вообще не исполнится (ошибка раньше, CSP, старый браузер), форма отправит исходные блоки, а не пустоту. Мина обезврежена в источнике. Заодно уходит `raw()` в одинарных кавычках — `hidden_field_tag` экранирует штатно, апостроф и `</script>` в тексте блока перестают ломать разметку.

Побочный выигрыш: при падении валидации (`render :edit, status: :unprocessable_entity`) редактор теперь восстанавливает набранное, а не показывает пустоту.

Создание новой записи не меняется: `#new` задаёт `body_blocks: []` → `value == '[]'`, байт в байт как сейчас.

### Контроллерный guard

Вариант «не затирать непустые блоки пустым массивом» **отвергнут**: ломает легитимное «удалить все блоки», причём молча — UI показал бы ноль, БД хранила бы старое.

Вместо него — маркер живого редактора: скрытое поле `body_blocks_editor`, JS ставит `'1'` только после успешного boot; контроллер игнорирует пустой массив без маркера у записи, у которой блоки есть. Два input'а и три строки в `assign_body_blocks_from_form`. Ложных срабатываний нет: единственный отсечённый сценарий — очистка блоков curl'ом без маркера.

### Как проверяется без браузера

После фикса JS читает ровно ту строку, которую отрендерил сервер, — значит утверждение о содержимом `value` и есть регресс-тест. Ключевые примеры: `Nokogiri` достаёт `#lc-blocks-json['value']`, парсит и сверяет с `record.body_blocks`; round-trip текста с `'`, `"`, `<`, `&` и кириллицей; отсутствие `data-lc-initial` в HTML; PATCH исходным JSON не трогает `body_html`; PATCH пустым массивом с маркером очищает, без маркера — нет.

Ручной smoke остаётся в чек-листе PR: открыть лендинг с блоками, нажать «Сохранить» ничего не меняя, убедиться что текст на месте.

## PR-B — Фаза 2: админка ЖК

### Извлечение блок-редактора

Вводим `app/views/admin/shared/` (директории нет, конвенцию заводим): `_block_editor.html.erb` (разметка :55-78 + скрипт :122-319) и `_admin_form_styles.html.erb` (`<style>` :102-120, владелец `.admin-input`).

Locals — четыре, данные вместо модели, чтобы партиал остался model-agnostic:
```erb
<%= render 'admin/shared/block_editor',
      param_name: 'residential_complex[body_blocks_json]',
      blocks:     complex.body_blocks || [],
      upload_url: upload_image_admin_residential_complexes_path,
      prefix:     'zhk' %>
```

Коллизия двух инстансов решается префиксом id (`#{prefix}-blocks`, `-blocks-json`, `-add-menu-btn`, `-add-menu`) плюс обёрткой `<div id="#{prefix}-editor">` и заменой `document.querySelectorAll('.lc-add-btn')` (:309) на `root.querySelectorAll(...)`. Презентационные классы (`lc-block-card`, `lc-list-items`, `lc-faq-pairs`, `lc-img-preview`, `lc-block-body`) не префиксуем — они держатся замыканиями, кросс-инстансных селекторов по ним нет.

Попутно чиним несъёмный `document.addEventListener('click')` (:306) — самоудаление при отсоединённом узле, иначе каждая Turbo-навигация оставляет слушателя на мёртвом DOM. Сносим мёртвые `_uid` и `lc-form`.

**Не трогаем** дублирование словаря видов блоков в пяти местах (`LandingContent::BLOCK_KINDS`, меню :61-69, `makeBlock`, `kindLabel`, `LandingBlocksHelper::KIND_RENDERERS`) — унификация требует ERB→JS моста и правки живого рендерера при нулевом пользовательском эффекте. `# TODO(refactor)` со списком мест.

Upload: тело `upload_image` (`landing_contents_controller.rb:85-99`) переезжает в concern `Admin::UploadsBlockImages`, у каждого ресурса свой `collection { post :upload_image }`. Чужой роут не переиспользуем — сцепило бы несвязанные ресурсы, и строка лога начала бы врать.

Стили: `.admin-input` живёт в партиале, не в `application.tailwind.css`. Причина — `app/assets/builds/` в git пуст, CSS собирается на деплое, в seo-worktree сборку проверить нечем, а внутри `@layer components` правила подпадают под tree-shaking. Размен на дублирующийся `<style>` в двух формах, зафиксировать тикетом.

### Роуты

`config/routes.rb`, сразу после :666:
```ruby
resources :residential_complexes, only: %i[index new create edit update] do
  member do
    get  :listings
    post :attach_properties
    post :detach_property
    post :publish
    post :unpublish
    post :soft_delete
    post :restore
  end
  collection { post :upload_image }
end
```
`show` опущен по конвенции админ-разделов (index → edit). `destroy` опущен сознательно: слаг ЖК — публичный URL, soft-delete + `restore` закрывают операционные нужды. `listings` — отдельный экран, а не секция формы: там пагинация и фильтры, `?page=` на форме терял бы несохранённые правки.

### Контроллер

`app/controllers/admin/residential_complexes_controller.rb` — скелет как у всех (`include AdminTokenAuth`, `layout 'application'`), поиск через `ResidentialComplex.unscoped.friendly.find` (образец `Admin::CaseStudiesController`).

Табы — четыре: все / опубликованные / черновики / **удалённые**. Четвёртый обязателен, иначе soft-delete необратим без консоли.

Счётчик объектов в списке — **один** grouped-count, не `on_site_listings_count` в цикле (он мемоизирован per-instance и дал бы 50 запросов). Комментарием, иначе следующий читатель «упростит» обратно.

Strong params — плоский список полей; **`address_patterns` в permit не входит**. Форма шлёт `address_patterns_text` (textarea, паттерн в строке), контроллер нормализует `split("\n") → strip → reject(&:blank?) → uniq`. Проверка на `nil`, а не `blank?`, — пустая textarea должна очищать массив. Причина против `permit(address_patterns: [])`: массивные поля требуют JS для добавления строк, а полное очищение без hidden-заглушки невозможно, с заглушкой приходит `[""]`.

Привязка — `update_all`, а не итерация с `update!`: `after_commit` в `property.rb:251-258` дёрнул бы IndexNow и Я.recrawl на каждый объект, а Фаза 4 прямо запрещает уведомлять поисковики на привязку (квота 150/день, привязок при наполнении сотни). `updated_at` выставляем руками — Фаза 4 читает его для sitemap `lastmod`. Прецедент в проекте — `Admin::PropertiesController#toggle_force_publish` через `update_columns`. Обязателен комментарий, иначе снимут на ревью.

`restore` возвращает ЖК **черновиком**, а не в прежнем статусе — иначе удалённый-и-возвращённый мгновенно снова в проде, минуя ревизию текста.

### Coverage

`app/services/zhk/coverage.rb` — критерии дословно те же, что в уже написанном `lib/tasks/zhk.rake` (нет текста / нет фото / нет объектов / не опубликован), rake переводится на сервис, чтобы админка и консоль не разъехались. `photo_counts_by_slug` — один glob по `public/images/zhk/*`, не по глобу на строку.

Плюс предупреждение о дублях первого абзаца `body_plain` — риск 4 канонического плана (шаблонная проза по ЖК одного застройщика).

### Экран привязки объектов

Реальность, из которой исходим: у всех 7 засеянных ЖК **нет координат** (сид их не заполняет), а у 12 из 18 `on_site` объектов не заполнен район. То есть «правильная» цепочка критериев на сегодняшних данных даёт пустой экран.

`app/services/zhk/attachment_suggester.rb` — `Result(strategy, candidates, notes, pool_size)`, стратегии выбираются каскадом (elsif, не union — union залил бы оператора инвентарём целого района):

1. **радиус** `within_radius(lat, lng, 0.3)` — если есть координаты; `geom` заполнен у 100% объектов;
2. **паттерны** — `address ILIKE` по `address_patterns`, каждый через `sanitize_sql_like`;
3. **район** — только через `RyazanDistricts.aliases_for(slug)`; метод возвращает `nil` для неизвестного слага, поэтому `Array(...).presence` обязателен, иначе `where(district: nil)`;
4. **none** — сигналов нет, `Property.none` + человеческие `notes`.

Оператор может перекрыть выбор из UI: расширить радиус, взять район принудительно и — ключевое — **`strategy=all`**: все непривязанные `on_site` с поиском по адресу. Сегодня это 18 строк и единственный работающий способ привязать хоть что-то, пока координаты не проставлены. Пагинация (kaminari, per 30) делает стратегию жизнеспособной при росте каталога; в UI оговорка, что выбор не переносится между страницами.

`notes` пишем словами, а не молчим: «у ЖК не заданы координаты — радиус-поиск недоступен», «у 12 из 18 объектов не заполнен район».

Экран `listings.html.erb`: секция привязанных (все, не только `on_site`, со статус-бейджем и «Отвязать») + секция кандидатов (плашка стратегии, переключатель, поиск, чекбоксы, «Привязать выбранные»).

### Форма ЖК

Пять fieldset'ов: ОСНОВНОЕ (`name` обязательно, `slug`, `published`), ЛОКАЦИЯ (`city` из `CITY_NAMES`, `district_slug` из модуля города, `address`, `address_patterns_text`, координаты), ФАКТУРА (`developer`, годы, корпуса, этажность, материал, два enum-селекта с `include_blank`), ИНФРАСТРУКТУРА (5 чекбоксов), SEO (`title`, `meta_description`), КОНТЕНТ-БЛОКИ (общий партиал).

Координаты — с красным hint'ом «без них подсказчик объектов не работает». Поле слага нужно: модель генерирует слаг ровно один раз, после создания сменить его можно только этим полем; на edit — предупреждение, что это публичный URL и позиции просядут.

Зависимость «район от города» — без JS: список рендерится из модуля сохранённого города плюс подпись «смените город и сохраните, список обновится». Каталог сегодня рязанский, модель валидирует.

Карточка после SEO-лендингов в `app/views/admin/dashboard/index.html.erb:117-135` + `@zhk_counts` в `Admin::DashboardController#index:36-39`. Четыре счётчика, включая `sitemap_ready` — это гейт Фазы 3, пусть редактор видит прогресс.

## Риски

1. **Регрессия редактора лендингов при извлечении** — главный. Митигация трёхслойная: спеки PR-A приезжают раньше и служат сетью (это и есть решающий аргумент за такой порядок PR); коммит переезда чистый и читается как rename; ручной smoke в чек-листе.
2. **ЖК без координат (все 7)** — экран кандидатов иначе пуст в 100% случаев. Закрыто стратегией `all`, переключателем и красным hint'ом на форме.
3. **Объекты без района (12 из 18)** — район не может быть основной стратегией; `aliases_for` обязателен; значения вне реестра («Рязанский», «Белореченский») просто не совпадут, падения нет.
4. **`update_all` минует колбэки** — намеренно, ради квоты Я.recrawl; `updated_at` руками; без комментария снимут на ревью.
5. **N+1 на index** — один grouped-count и один glob, оба с комментарием против «упрощения».
6. **Битая публичная ссылка** — `/zhk/:slug` появится только в Фазе 3, поэтому в админке путь показываем текстом, а не ссылкой.
7. **Общие поверхности с upgrade-сессией** — `app/views/admin/**` они не трогают (подтверждено), но `config/routes.rb` и `admin/dashboard_controller.rb` общие; хунки держать минимальными.
